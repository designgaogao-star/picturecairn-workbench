# 清理后的 Review

日期：2026-10-19。范围：接手清理产生的变更、运行入口、打包产物和数据边界。已对照清理前源码快照检查，不把格式化通过等同于行为正确。

## 保留的原有问题

1. **P1：回收站校验是事后检测。** `gallery/remove.py:92` 使用 SHFileOperation，`recycle_one_verified()` 在删除后比较回收站占用。现有实现仍不能保证配额不足时绝不发生永久删除；检测告警无法恢复已经丢失的文件。需要专门改造失败语义，本轮没有对真实图库执行删除，也不宣称删除链路已完全安全。
2. **P2：冷启动扫描仍阻塞服务。** `gallery_server.py:1192` 在绑定 HTTP 端口前扫描，而 `electron/main.js:91` 只等待 90 秒。历史全量测量为 167 秒，空数据目录或大量指纹失效时仍有启动超时风险。性能改造留待清理后的下一阶段。

## 本轮发现并修复

- 浏览和旧 SQLite 清单都只返回图片，拒绝从图片接口读取视频。没有删除用户原始文件或旧数据库中的记录。
- 整包确证检查所有文件，独有的非图片内容会阻止整包删除；空壳判断不会忽略其他文件。
- 删除超大文件“仅比较头尾”的确证捷径，内容确证按块读取完整文件。
- 去重索引、锁和日志统一使用可写数据目录，修复安装目录和用户数据目录混用。
- 补齐 SciPy 依赖及 gallery 子包声明。打包版使用后端 exe 的索引入口，成功在 C 盘临时图库与 F 盘程序之间建立索引。
- 移除 electron-builder 和不包含后端的构建路径；排除本机环境里被自动发现的 Torch 等无关依赖。
- 修复入口以 `__main__` 运行时再次导入 server 导致的状态实例分离，标记和进度可立即从运行服务读回。
- 修复索引锁探测失败时未关闭文件句柄，以及本轮清理中暴露的跨盘路径判断错误。
- 图片查看器去除视频分支，保留原图、预览、缩放、旋转和全屏；快速切组时过期请求不再覆盖后来的响应。
