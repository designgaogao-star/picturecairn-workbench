### 图片内存定位与修复

用相同合成素材、Electron 和后端分别对照墙面滚动、连续静态图和 GIF/WebP 进出。仅解除已完成 img 的 src、撤销 Blob 与清空四张预载虽有改善，仍不能解释和控制全部私有内存保留。诊断中的手工 GC、Blink 闲置资源清理表明应同时处理浏览器原生资源，不能只看 JS 堆就断言没有增长。

生产方案在实际图片离开 UI 时发释放提示，独立沙箱预载一秒合并检查；通过只向当前同源渲染器开放的 IPC 读取私有内存，超过 `max(128 MiB, Blink 图片缓存 liveSize + 96 MiB)` 后调用 webFrame.clearCache，十秒内不重复回收。软阈值不是进程硬上限，liveSize 也不代表所有已解码像素。回收不清 HTTP／磁盘缓存，不额外强制 GC、不注入调试协议内存压力、不结束进程；Electron 的公开回收 API 内部本身会通知当前进程的内存压力监听器。普通浏览器仅使用资源解除引用逻辑。
