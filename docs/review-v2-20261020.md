# GalleryTool V2 Review 与验收

日期：2026-10-20。范围：图库索引、图片请求链路、整理任务、删除、迁移、类型契约、Windows 桌面包与运行入口。真实图库只做读取与索引；删除验证使用临时文件。

## Review 后修复

- **扫描抢占**：整目录枚举曾一直持有源卷预算，冷图请求可能等待数秒。改为逐条枚举释放预算；并发回归先复现失败，再确认前台读取能在下一条文件元数据前执行。SHA-256 核验也在每 1 MiB 读取之间让出磁盘。
- **事件流与退出**：FastAPI 0.148 的生成器保活任务在断开时产生 BrokenResourceError；Python 3.14.6 Windows Proactor 的 socket shutdown 异常会漏掉 transport 清理。改为直接返回内置 SSE 响应并采用标准 Selector 事件循环。连续断开、重连与保留事件连接时退出均纳入实际进程回归，服务日志不得出现 ERROR。
- **分页一致性**：总数、条目和图库索引版本改为在同一 SQLite 读事务中获取；图库列表统一使用 offset/limit 和 Page 响应。
- **打包目录边界**：仅排除 PyInstaller 内部资源目录会把桌面图标和旧缓存重新索引。新增应用目录配置，并在首次迁移和重启后排除旧数据目录；回归先复现两张误收录图片，再验证只剩原图。
- **定向扫描边界与取消**：每个待枚举目录都经过统一 Access 校验，拒绝已经替换成 junction 的路径；取消清理覆盖拿到扫描锁后的整个准备和枚举过程，避免任务已取消但图库仍显示扫描中。
- **浏览位置**：补齐旧库未保存图片清单时的延后恢复；位置一旦绑定图片 ID，后续扫描不再以旧下标覆盖它。
- **图片生成**：同素材对照发现统一 WebP 编码拖慢冷预览。不透明图改用 JPEG，透明图使用 WebP；处理流程版本进入缓存键。热缓存不访问原图，也不计算去重哈希。
- **删除及日志**：扫描和删除共享图库锁；回收逐项确认结果，COM 错误转为明确失败。操作记录关联 task_id，取消后仍能查询已执行项目，永久删除严格要求 JSON true 确认。
- **旧链路清理**：移除旧 HTTP 服务、全局前端、去重脚本编排及人工探针；保留入口转发、原始数据、快照和旧日志。

## 性能

原图位于 F 盘，索引与新缓存位于本机 C 盘。后台扫描运行期间使用脚本测量，以下为本轮最终记录，不使用历史预期值代替实测。

| 项目 | 实测 | 目标 |
|---|---:|---:|
| 打包后端带真实索引就绪，3 次 | 0.58–0.65 秒 | 不超过 2 秒 |
| 就绪时 RSS | 约 72 MiB | 记录值 |
| 健康接口 P95，80 次 | 4.61 ms | 不超过 50 ms |
| 100 张图片清单 P95，30 次 | 34.59 ms | 不超过 100 ms |
| 热缩略图 P95，50 次 | 23.99 ms | 不超过 50 ms |
| 100 个组清单 P95，30 次 | 35.56 ms | 记录值 |

同一批 12 张图片、1600 档位，交替先请求 V1/V2。此对照在调度修正后、最终路径边界复核前完成。两边派生缓存预先确认均未命中，操作系统缓存没有冲刷；V2 同时进行后台扫描。P95 使用 nearest-rank，样本量仅 12，不当作完整图库的尾延迟保证。

| 项目 | V1 | V2 |
|---|---:|---:|

| 首请求 P95 | 1818.61 ms | 1216.74 ms |

冷图中位延迟与内存仍高于 V1；V2 的收益主要是服务先就绪、稳定的清单与热缓存、受控并发和可中断的后台工作。进程 IO 包含数据库及并发后台活动，不能解释为物理盘吞吐。未宣称所有图片和负载都比 V1 快。

最后一次从启动 --quit 命令到桌面及子后端退出共 9.38 秒，其中包含从机械盘启动第二个 Electron 进程的时间；服务日志中的后端 shutdown 为 0.24 秒，没有触发超时强杀。此前热启动命令测量为 0.77–0.80 秒。

复测工具为 `scripts/benchmark_v2.py`、`scripts/compare_loading.py`、`scripts/measure_startup.py`。原始 JSON 和截图位于被 Git 忽略的 `output/`。
