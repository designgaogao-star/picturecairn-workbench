# V2 架构

## 所有权

`gallery.__main__` 是源码和打包程序的统一入口。`gallery.app` 只处理 HTTP、输入模型与响应；`Service` 持有数据库、资源预算、索引、图片服务和任务管理器，不依赖模块全局实例。

| 模块 | 职责 |
|---|---|
| `paths` / `config` | 代码、资源、数据路径与图片格式 |
| `catalog` / `sql` | SQLite、显式迁移、ID、分页、浏览记录与审计记录 |
| `indexer` / `watcher` | 文件元数据、变更监听、目录对账与离线状态 |
| `access` | 从 ID 解析真实路径，拒绝越界和嵌套链接 |
| `jobs` / `events` | 有界任务、取消与暂停、磁盘及解码预算、变更通知 |
| `images` | 固定尺寸、方向、颜色、透明度、动图首帧与磁盘缓存 |
| `hashing` / `dedup` / `audit` | pHash、分块相似分析、完整内容比较与辅助整理证据 |
| `organize` / `recycle` | 抽样、删除、逐项 Windows 回收结果和日志 |
| `migration` | 一致快照与旧状态导入 |

`gallery_server.py` 仅保留入口转发；旧 HTTP server、脚本编排和共享全局前端已移除。

## 数据与扫描

目录结构是权威内容来源，SQLite 是浏览查询与用户状态的权威来源。所有根目录有独立 ID；目录、图包、图片使用持久 ID。在可确定身份时通过 NTFS 文件 ID 保留改名后的引用，硬链接分别建记录。

源图片增删只影响对应目录，列表请求不扫描文件系统。失败目录保留旧记录并报告错误；根目录离线不意味着内容消失。首次和启动校验可后台逐文件扫描；每十分钟检查目录变化，每小时完整核对一次。文件监听触发的目录扫描强制核对文件，用户也可显式刷新。

维护间隔由 GALLERY_MAINTENANCE_INTERVAL 或 --maintenance-interval 配置；--no-scan 同时关闭启动与维护扫描。异常或取消将扫描状态置为 interrupted，重启清除残留 scanning/pending。待处理的同图库扫描合并，正在执行的扫描允许留一个后续扫描，以免遗漏枚举期间新发生的变化。

根目录的工作区隐藏目录、应用和数据目录不属于图库内容。图包内部的隐藏文件、非图片文件、不能跟随的链接都不能在完整内容比较中被忽略。无法完整枚举或读出时，核验返回失败。

桌面通过 GALLERY_APPLICATION 将整个应用目录交给后端排除，不能只排除 PyInstaller 的内部资源目录。已迁移的旧数据目录在首次迁移和重启后都排除；旧数据与图库根相同时只排除其 cache/thumbs，保留根目录中的原图。

图片排序使用 Python `lower()` 预计算 SQL 排序键，沿用旧 `(album.lower(), rel.lower())` 规则。位置绑定图片 ID。单张上下文只在所属图包内返回相邻 ID。

分页的总数、条目和图库版本在同一个 SQLite 读事务中获取，避免扫描期间返回来自不同快照的值。

分组/图包详情与封面由索引直接查询；先确定首个非空图包，再取包内首图，避免按组对所有图片做封面排序。present=0 的历史记录保留供稳定 ID、浏览引用和审计使用，清单排除且详情返回 404；不执行后台破坏性清理。

## 调度与资源

后台队列最多 128 个等待项、两个 worker。图片队列最多 64 项、两个 worker；按缓存键合并前台重复请求，前台冷读优先于后台 IO。同一源卷默认一次冷读，解码并发不超过二，总估算预算 512 MiB。

图片头读取与首帧物化分别占用源卷名额；等待解码预算、缩放、颜色转换、编码及写入派生缓存不占用源卷名额。解码预算对等待中的前台请求优先分配，pHash 后台构建也在源卷名额外等待预算，避免等待内存时挡住看图。预算覆盖全部图像对象的生命周期，退出和失败均先关闭图像再归还预算；读取前重新核对源文件版本。

预热在单张图片之间暂停。持有生成锁或解码预算时只检查取消，当前图片结束并释放资源后才等待继续，避免暂停任务长期占用看图所需资源。等待生成锁期间可以暂停和取消。

预览长边为 400、800、1600、2560、4200。不透明图使用 JPEG，透明图使用 WebP；同素材测量显示，统一 WebP 编码会拖慢冷预览。缓存键含图片版本和处理流程版本，目录分片，热缓存不 stat 原图。默认软预算 12 GiB，通过访问时间回收至预算的 85%；回收只涉及新缓存，不涉及原图和旧缓存。

图片及封面提供不透明版本，匹配版本的 URL 使用一年 immutable 缓存，不匹配返回 409；无版本 URL 保持条件请求。前端缩略图 fetch 并发 4、等待上限 128，接近可见区才加载，卸载即取消并释放 Blob。预热使用图包及图片排序键的 keyset 分页。

扫描与删除使用相同的图库互斥锁，文件系统工作在数据库事务外。任务更新会持久保存；重启后未完成任务标为 `interrupted`，可重新提交，索引和封面按版本复用。

schema 7 为任务增加 trigger。目标名称、相对路径、所属图库和分组由持久 ID 解析；任务可按类型、状态、图库和活动状态筛选分页。最终计数及取消时的部分删除结果保留。SSE 附带影响范围与可观察心跳，重连继续用当前快照恢复。

## 去重与删除

新 pHash 固定为原图 JPEG draft、32×32 灰度 Lanczos、DCT、64 bit。旧库同时包含缩略图和原图来源，统一标记旧版本；后台补索引生成新规范，分析只使用相同规范且文件版本仍有效的哈希。

相似度分块计算，候选写 SQLite；不持有 N×N 常驻矩阵。图包完全一致与包含结论通过所有文件的完整 SHA-256 和数量匹配得到，独有文件按任务分页查看。pHash 候选与启发式整理报告不自动触发删除。

完整内容核验每读取 1 MiB 重新竞争源卷预算，使前台冷图请求能够在分块之间优先执行。暂停和取消也在这个边界生效。

默认删除使用 Windows `IFileOperation`，进度回调拒绝永久删除分支，并以逐项结果与回收目标判断完成。不可回收、COM 错误和用户中止均记录失败，不自动改用永久删除。数据库保存操作意图与结果，另写追加日志；中断后的 `pending` 记录保留供核查。

## 桌面与构建

Electron 44 使用隔离渲染进程、沙箱和有限的目录选择 IPC。新后端使用动态端口与随机会话握手。退出先请求后端停止任务，超时才结束其所属进程；复用的外部后台服务由自身管理。

本机启动脚本读取被忽略的 runtime.local.json，显式参数和 GALLERY_DATA 优先；便携程序可从相邻的 GalleryTool.local.json 读取 dataDirectory。配置不进入构建包或 Git，避免把本机图库路径分发给其他用户。

SSE 使用 FastAPI 的 EventSourceResponse 和标准编码，直接返回流式响应，由响应管理客户端断开。Windows HTTP 服务使用标准库 Selector 事件循环，避免 Python 3.14.6 Proactor 在连接重置后漏掉 transport 清理而卡住退出；后端不在事件循环中运行子进程。

Python 和 npm 依赖分别锁定于 uv.lock 与 package-lock.json。唯一构建入口为 scripts/build.ps1；生成契约与构建正式前端后，PyInstaller onedir 产物包含 SQL、ui/dist 与原生计算依赖，Electron 资源包含桌面脚本与图标。后端同源托管 ui/dist，前端使用 hash 路由，不需要服务端页面回退。prototype 保留在源码中，不进入新桌面包。构建和用户数据不进入 Git。

正式前端的所有 JSON 请求使用类型客户端。客户端可注入 HTTP transport；ui/src/api.ts 在开发只读模式中于此拒绝全部非 GET 请求，避免不同视图遗漏检查。生产构建不启用该限制，后端权限、路径校验及文件操作规则不依赖此开发开关。
