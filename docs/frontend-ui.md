# GalleryTool V2 前端 UI/UX 说明

这份文档说明正式前端 `ui/` 的设计与交接事项：
- 界面结构、视觉规范、交互方式与状态设计；
- 交付时的验证结果；
- 留给前端负责人继续的事项。

技术栈为 Preact 10、@preact/signals、Vite 和严格 TypeScript。文中引号里的文字都是界面上的实际文案。接口缺口另见 `docs/frontend-gaps.md`。

## 1. 设计原则

- **打开即是工具。** 直接进入上次使用的图库，没有落地页。
- **浏览优先。** 图片占据主要面积。底色是深色中性色，界面元素对比度低，不抢画面。
- **层级与磁盘一致。** 层级为“图库 → 文件夹 → 图包 → 图片”，面包屑和侧栏都按这个顺序组织。
- **规模大也流畅。**
  - 列表全部虚拟滚动，分页读取。
  - 请求并发有上限，不在可见区内的内容不加载。
  - 快速切换时会取消或忽略过期请求。
- **破坏性决定由用户做。**
  - 相似度只作提示，删除依据是逐字节核验的结果或用户自己的判断。
  - 删除默认移到回收站，并逐项报告结果。
- **状态如实。** 加载中、元数据未补齐、离线、失败、扫描中断都有明确的界面，不显示假进度。

## 2. 信息架构与路由

页面状态都在路由里：刷新、前进后退、复制链接都会回到同一位置。

| 层级 | 视图 | 路由 |
|---|---|---|
| 图库 | 文件夹首页 | `#/l/<lib>` |
| 文件夹 | 图包墙 | `#/l/<lib>/g/<group>` |
| 文件夹 | 抽样 | `…/samples` |
| 文件夹 | 整理 | `…/organize[/t/<tab>]` |
| 图包 | 图片墙 | `…/p/<pkg>` |
| 图片 | 查看器（覆盖在图片墙上） | `…/p/<pkg>/i/<img>` |

整理视图分三个标签：相似图包、整包核验、清理检查。

## 3. 布局

### 桌面（宽度大于 860px）

- **顶栏**（高 50px）：
  - 侧栏开关；
  - 面包屑（图库 / 文件夹 / 图包）；
  - 缩略图尺寸（小、中、大）；
  - 连接状态图标（只在断开或连接中时出现）；
  - 后台任务按钮，角标显示进行中的任务数。
- **侧栏**（宽 284px）：
  - 图库切换和“添加图库”；
  - 文件夹列表，可按标记状态和分类（R16 / R18 / 非R18 / 其他）筛选；
  - 可重新扫描整个图库或单个文件夹；
  - 底部显示扫描状态和上次扫描时间，悬停显示图库路径。
- **文件夹标题栏**：
  - 视图切换：图包、抽样、整理；
  - 文件夹标记：未标记、保留、待整理；
  - “继续浏览”按钮；
  - 更多菜单，其中有“预先生成缩略图”。
- **查看器**：全屏覆盖，底部有胶片条，右侧信息面板可开关。全屏时胶片条浮在画面上。
- **任务抽屉**：从右侧滑出，显示后台任务、进度和删除报告，顶部显示缩略图缓存占用。
- **提示条**：右下角堆叠。需要处理的提示带操作按钮，例如“重试”“查看结果”。

### 窄屏（宽度不超过 860px，按 390×844 验证）

- **侧栏**：默认收起；打开时以覆盖层滑入，背后有遮罩。点遮罩或选中文件夹后自动收起。
- **顶栏与标题栏**：
  - 面包屑最宽占视口的 44%，超出部分截断；
  - 标记按钮只显示图标；
  - “继续浏览”隐藏“第 N 张”；
  - 图片墙隐藏副标题。
- **查看器**：
  - 底部固定“上一张 / 位置 / 下一张”，到图包边界时对应按钮变淡；
  - 信息面板改为在页面内展开；
  - 触屏可左右滑动切换图片，也可双指缩放。
- **提示条**：贴底铺满；在查看器里上移，避开底栏。
- **触屏设备**（`hover: none`）：卡片标题和角标始终显示。

## 4. 视觉规范

设计令牌集中在 `ui/src/styles/base.css`。

**颜色**

| 用途 | 令牌与取值 |
|---|---|
| 界面底色（5 级） | `--bg` #0e1014 → `--bg-1` → `--bg-2` → `--bg-3` → `--bg-4` #2c323e |
| 图片底色 | `--media` #090a0d，比界面更暗，用来衬托图片 |
| 分隔线 | `--line` #262b35、`--line-2` #363d4b |
| 文字（3 级） | `--text` #e7e9ee、`--text-2` #a3aab7、`--text-3` #6f7686 |
| 强调色 | `--accent` #6aa5ff，用于选中、当前位置和主按钮 |
| 状态色 | ok #4fc58d、warn #e8b64c、bad #f26d6d，各配一个约 15% 透明度的浅底 |

**形状**：圆角 6、8、12px；阴影只用于浮层。

**字体**
- 字体族：Segoe UI Variable，回退到微软雅黑 UI。
- 字号：

  | 用途 | 字号 |
  |---|---|
  | 正文 | 14px |
  | 标题（h1 / h2 / h3） | 20 / 15 / 13px |
  | 按钮（常规 / 小 / 迷你） | 13.5 / 13 / 12px |
  | 提示文字 | 12.5px |
  | 辅助文字 | 12px |
  | 角标 | 11.5px |

- 数字一律使用等宽数字（tabular-nums），并统一千位分隔，例如“8,120 张”“4,061 / 8,120”。

**按钮高度**：小按钮 28px，迷你按钮 24px；窄屏查看器底栏按钮 38px，方便触控。

**图标**：线性图标（`ui/src/lib/icons.tsx`）。默认 18px，按钮里 16px，迷你按钮里 14px。

**缩略图**：
- 加载时显示脉冲底色，图片以 0.18 秒淡入。
- 失败时在卡片内显示原因；可以重试的失败另有“重试”按钮。

## 5. 交互

### 浏览

- 首页卡片显示文件夹封面、名称和数量。
- 逐层进入：图包墙 → 图片墙 → 查看器。按 Esc 或点击面包屑返回。
- 图片墙只显示静态封面，动图标“动图”角标，不在墙上播放。GIF/WebP 动画在查看器里播放。
- 以下设置保存在本地：图库、筛选条件、缩略图尺寸、侧栏开关。

### 查看器快捷键

| 按键 | 作用 |
|---|---|
| → 或 PageDown | 下一张 |
| ← 或 PageUp | 上一张 |
| Home / End | 本图包第一张 / 最后一张 |
| Esc | 关闭查看器，回到图片墙并定位到刚看的图片 |
| F | 全屏 |
| 0 | 适应窗口 |
| 1 | 原始大小 |
| + / - | 放大 / 缩小 |
| R / Shift+R | 顺时针 / 逆时针旋转 |
| I | 信息面板 |
| Delete | 删除当前图片（先进入删除确认） |
| U / K / M | 文件夹标记：未标记 / 保留 / 待整理 |

查看器的行为：
- **不跨图包。** 到达边界时停住，提示“已是本图包最后一张”（或第一张），并提供“下一个图包”（或“上一个图包”）按钮，由用户决定是否继续。
- **位置显示**为“当前 / 总数”，带千位分隔。位置或总数还不知道时显示“…”。
- **原图加载期间**，先放大显示已有的缩略图；没有缩略图时保留上一张画面。快速连按时，过期的请求会被取消或忽略，只显示最后停下的那一张。
- **动图**（GIF/WebP）在查看器里正常播放。

### 位置恢复

- 浏览位置绑定图片 ID，每个文件夹记录一个，写入后端。
- 文件夹标题栏的“继续浏览”显示“第 N 张”，悬停可看到上次的图包和图片名，点击直接回到那张图片。
- 关闭查看器后，图片墙滚动到刚看的图片，并用描边标出。
- 刷新后停留在同一视图。

### 选择与删除

1. **选择**：在图片墙或图包墙进入选择模式，勾选图片或图包。按 Esc 退出选择模式。
2. **确认**：删除确认框默认选“移到回收站”，可以从 Windows 回收站恢复，删除日志会保留。
   - 选“永久删除”时，还必须勾选“我确认永久删除这些文件，且无法恢复”。
   - 确认框注明“提交后由后台任务逐项执行；结果会逐项列出，失败的项目保持原状。”
3. **执行中**：提交后对话框变成“正在删除”。这时可以关闭对话框，删除会在后台继续。
4. **结果**：完成后弹出提示，带“查看结果”。“删除结果”逐项列出：
   - 已移到回收站（或已删除）的数量；
   - 失败的项目及每项原因；
   - 任务被取消或中途失败时，说明已处理的项目见下表，其余项目没有执行。
5. 删除结果也可以随时从任务抽屉重新打开。

### 筛选与抽样

- 文件夹列表可按标记状态和分类筛选。没有结果时显示“没有符合筛选条件的文件夹”和“清除筛选”。
- 抽样从整个文件夹随机取图，用于快速判断文件夹内容。
  - 数量可选 20、40、100，可以换一批。
  - 同一个标签页里，刷新或从链接进入查看器，看到的仍是同一批。

### 整理与去重

**相似图包**
- 列出指纹相似的图包对和图片对，并标注差异值（0 表示几乎相同，最大 64）。
- 相似只是线索，这里不提供删除入口。

**整包核验**

逐字节比较两个图包的全部文件，包括非图片文件。结论只有以下几种：

| 结论 | 说明 |
|---|---|
| 两侧完全一致 | 保留其中一侧即可 |
| 左侧被右侧完整包含（或反过来） | 注明删除哪一侧不会丢失内容 |
| 两侧各有独有文件 | 注明删除任何一侧都会丢失内容 |
| 一侧或两侧没有文件 | 空图包不算被包含 |

只有核验结论才作为删除的依据。

**清理检查**
- 列出空壳包、含广告图、疑似不完整的图包，每条都附证据。
- 仅凭文件名判断的证据会单独标出。

### 任务进度

- 任务抽屉列出扫描、生成缩略图、相似分析、核验和删除任务。
- 每个任务显示状态（排队中、进行中、已暂停、正在取消等）、进度和计数，可以“暂停”“继续”“取消”。
- 预热暂停在当前图片完成并释放资源后生效，后台不会因暂停长期占用看图所需的解码名额；正在进行的原生解码或编码不会被强行中断。
- 已完成的任务保留结果入口。

## 6. 状态设计

| 状态 | 界面表现 |
|---|---|
| 加载中 | 卡片和缩略图显示脉冲占位；查看器先显示放大的缩略图，角落有加载指示 |
| 元数据未补齐 | 位置、总数、文件名等显示“…”，已有的信息先显示 |
| 动图 | 图片墙显示静态封面和“动图”角标，查看器里播放 |
| 无法解码 | 图片墙卡片显示“无法解码”角标，悬停可看原因。浏览器解不开的图提示“文件可能已损坏或格式不受支持”。不影响浏览其他图片 |
| 服务忙或短暂不可达（502–504） | 缩略图自动重试 3 次，间隔 0.7、1.4、2.8 秒，仍失败则显示“重试”。接口返回 503 时提示“后台队列已满或服务正在停止，请稍后重试” |
| 启动时连不上 | 显示“正在连接图库服务…”；失败后显示“无法连接图库服务”和“重试” |
| 使用中断开 | 先显示“正在重新连接图库服务…”；仍不通时显示“与图库服务的连接已断开”横幅和“立即重连”。已显示的内容仍可查看；恢复后自动重新读取快照，失败过的缩略图会再试一次 |
| 列表读取失败 | 在原位置显示错误和“重试”，已显示的内容不清空 |
| 扫描状态 | 侧栏底部和首页标题显示：正在扫描、等待扫描、索引完成、部分目录读取失败、目录离线、扫描中断、尚未扫描。没有对应的扫描任务时，残留的“正在扫描”显示为“扫描中断”，“等待扫描”显示为“尚未扫描” |
| 外部变化 | 后端推送变化后，当前列表自动刷新；正在看的图片已不存在时提示“这张图片已不存在”，并关闭查看器 |
| 空状态 | 没有图库时，首页直接显示“添加图库”表单。另外几种空状态见下 |

其他空状态：
- 图库里没有图片：“这个图库里还没有找到图片”。
- 扫描中：“正在扫描，文件夹会陆续出现…”。
- 筛选无结果：“没有符合筛选条件的文件夹”，并提供“清除筛选”。
- 没有任务或筛选无结果：“没有符合条件的任务”。

## 8. 工程集成与后续事项

**2026-10-21 已完成**
- 桌面构建：`scripts/build.ps1` 在 PyInstaller 前运行 `npm run ui:build`；`scripts/gallery.spec` 收录 `ui/dist`，`gallery/app.py` 同源托管正式前端。hash 路由无需服务端回退。`prototype/` 暂时保留，删除需另行确认。
- 添加图库：正式前端使用 `window.galleryApp.chooseDirectory()`，桌面显示“选择文件夹…”按钮，选择后填入路径。取消保留原输入；选择过程中禁止重复操作；失败显示原因并恢复按钮。普通浏览器继续手动输入。
- 只读模式：在 `api.ts` 的 HTTP transport 统一拒绝全部非 GET 请求，包含图库添加、扫描、预热、分析、核验、任务控制和删除，显示“只读联调模式”。仅在开发服务器中生效，生产构建忽略此参数；不会伪造操作成功。自动位置保存保留静默跳过，避免连续提示。
- 这是前端开发开关，不会禁止图片 GET 写入缓存，也不会禁止后端维护。真实数据排查仍只使用隔离副本；缺口 2 未在本轮处理。

**本轮验证**
- 实际产物：`build-out/20261021-232934/GalleryTool/GalleryTool.exe`，通过统一构建入口生成；同目录包含便携 ZIP。
- 实际 Electron 与打包后端验证：正式首页、目录选择 IPC、添加图库、浏览、GIF/WebP 像素变化、图包边界、位置保存与刷新恢复、任务、临时图片逐项删除。
- 目录选择使用受控系统对话框返回值，真实预载脚本与 IPC 均参与；没有自动点击 Windows 原生对话框。
- 开发模式 15 种写请求全部在发送前被拒绝，GET 正常；不带参数的开发模式及带参数的生产构建正常提交写请求。
- 截图覆盖 1440×1000 与 390×844，无横向溢出，见 `output/ui-qa/integration-1792596666394/`（桌面包）及 `integration-1792596666360/`（浏览器与打包后端）。全部素材为临时生成的几何图像。
