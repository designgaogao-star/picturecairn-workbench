# 当前界面审计

依据：`f5bb9cd` 的源码、`docs/frontend-ui.md` 和既有安全合成截图。这里只评价可观察到的结构和行为；没有开展用户访谈或可用性实验，不能把设计判断写成已测得的用户结论。

## 判断

当前界面已有配色变量、字体、页面规范、响应式与状态处理，并非完全没有规范。缺的是把这些规则组织成统一浏览体验：进入内容的路径、信息重要程度、静态图片的展示方式，以及整理操作何时出现。

| 优先级 | 现有证据 | 对使用的影响 | 新规则 |
| --- | --- | --- | --- |
| P1 | `ui/src/views/PackageWall.tsx` 的 `click()` 调用 `open(pkg.cover_id)`，图片墙放在角落图标 | 卡片主入口直接跳进一张图片，用户很难先判断图包有哪些内容 | 主入口打开图片墙；“继续浏览”是独立的直接看图入口 |
| P1 | `ui/src/views/ImageWall.tsx` 使用 `card-caption`；`ui/src/styles/walls.css:91` 默认隐藏、97 行悬停显现 | 扫看时看不到稳定文件名，图片名称与位置依赖鼠标来回探测 | 每张图片下方固定文件名与精简元数据，完整相对路径放信息面板 |
| P1 | `walls.css:120` 默认 `object-fit: cover`，图片卡片按 3:4 分配 | 横图和竖图都可能被截去关键内容，封面与原图边界混淆 | 图包封面允许裁切；图片墙固定方格中完整显示，填充是显式选项 |
| P1 | `GroupHeader.tsx` 同时排列图包/抽样/整理、三种标记、位置恢复及更多操作 | 视图、文件夹状态和命令看起来权重接近，浏览主线不突出 | 浏览/整理分模式；标记明确叫“文件夹状态”；维护命令放更多菜单 |
| P2 | `Topbar.tsx`、`GroupHeader.tsx`、`SelectionBar` 分别贡献工具行，背景与边框变化很小 | 不是行数本身有错，而是难以一眼分辨位置、模式和当前操作 | 位置栏、标题/模式区、单条上下文工具栏有明确职责；选中后原位替换工具栏 |
| P2 | `base.css` 主要是连续蓝灰暗色表面与蓝色强调；辅助标签大量使用弱色 | 整体像开发工具，图片与结构之间的层级不够鲜明；单一暗色没有覆盖日间桌面使用 | 提供中性浅/深主题，少量青绿选择色；正文与辅助文字设置明确对比要求 |
| P2 | 图包计数、标记、继续位置、角落图片墙入口都可能叠在封面上 | 多种徽标持续覆盖图片，同类信息分散在多个角落 | 图包数量与继续位置放文字区；封面只保留必要的动画/错误等内容状态 |
| P2 | 样式文件中未见统一 `prefers-reduced-motion` 规则 | 减弱动效偏好没有设计层面的统一约束 | 令牌级控制时长，减弱模式取消位移、淡入和连续动画装饰 |
| 保留 | `VirtualGrid.tsx`、`lib/paged.ts` 与 `lib/preview.ts` 已有虚拟化和请求边界 | 这是大图库可用性的基础，不应因新布局丢失 | 保留数据层与预算，只调整几何尺寸和内容呈现 |
| 保留 | `Compare.tsx` 已区分视觉相似、文件核验、独有内容和过期结果 | 正确表达删除依据，比“相似度百分比”更有价值 | 强化结论位置和两侧对比，继续保留完整语义 |
| 保留 | `DeleteDialog.tsx`、`TasksDrawer.tsx` 已处理逐项结果、取消、失败与历史 | 工程状态完整，不需要重写后端编排 | 复用真实状态，重新安排面板与决策呈现 |

## 设计风险与取舍

图片墙改为完整显示，会留下余边；这是保留图像信息的明确取舍。需要密集扫封面时可以切换填充，不能在加载失败时自动切换或改变格子比例。

图包先进入图片墙，多一个进入查看器的动作；换来可见的包内容、位置和总数。已有浏览记录用“继续浏览”一步恢复，保留高频连续阅读效率。

不做瀑布流。混合比例可以更有画廊感，但会增加虚拟化、滚动锚点和缩放恢复的复杂度。第一轮采用稳定等格网格，体验质量由准确内容、清晰层级和响应来实现。

侧栏第一轮仍是图库下的一级文件夹列表。不能把当前分组伪装成完整磁盘树；任意目录展开还需要明确的目录到内容查询语义，见 `delivery.md`。

浅色不是图片浏览的唯一正确答案。提供深色工作台，查看器始终中性深色；最终视觉验证必须覆盖两种主题，不用换主题来掩盖低对比文字。
