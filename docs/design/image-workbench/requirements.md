# 图片工作台设计要求

这份文档定义下一轮正式前端的目标行为。`preview/` 是关键流程样例，不等同于完整产品实现。

## 1. 体验主线

```text
图库 → 文件夹 → 图包墙 → 图片墙 → 单张查看
                    ↘ 继续浏览 → 上次图片
文件夹 → 整理 → 抽样 / 相似图包 / 整包核验 / 清理检查
全局 → 后台任务面板 → 状态 / 结果 / 控制
```

- 应用打开直接恢复上次有效位置，不显示欢迎页。
- 第一次没有图库时只显示添加图库表单入口和空状态；桌面支持系统文件夹选择，浏览器支持手动路径。
- 卡片单击打开，不以双击作为唯一入口。图包卡片打开图片墙，图片卡片打开查看器。
- 单图包文件夹允许沿用直接进入图片墙的优化，但标题仍保留文件夹与图包关系。
- 文件夹、图包、图片之间始终使用持久 ID。相同名称的资源不能合并，重命名不能靠旧显示名恢复。

## 2. 布局与尺寸

| 区域 | 桌面目标 | 作用 |
| --- | --- | --- |
| 左侧导航 | 232px；较窄桌面可为 216px | 品牌、图库选择、文件夹筛选和分页列表、索引摘要 |
| 位置栏 | 52px | 面包屑、外观、信息、任务入口 |
| 标题与模式区 | 约 132px，随必要的换行增长 | 当前名称、总数、继续位置、浏览/整理、文件夹状态 |
| 上下文工具栏 | 44px；窄屏 48px | 清单作用域、选择、完整/填充、尺寸、更多 |
| 主内容 | 桌面边距 24px，宽桌面 32px | 图片与整理工作面，自身滚动 |
| 图片网格 | 默认目标宽 230px，180–310px 可调 | 稳定等格布局，不因内容/悬停/错误改变行高 |
| 图包单项 | 封面 4:3，文字区 66px，圆角 6px | 文件夹图标、名称、张数、相对父路径、最近位置 |
| 图片单项 | 媒体格 1:1，文字区 66px | 完整图片、名称、尺寸、文件大小 |
| 信息面板 | 280px | 当前资源详情；不自动常驻 |
| 任务面板 | 360px | 任务筛选、状态、结果、控制与缓存摘要 |
| 状态栏 | 28px | 当前范围计数与精简状态，不承载主要命令 |
| 对话框 | 常规 480px，上限为视口减 32px | 添加图库、删除确认、逐项报告 |

桌面 1440px、1280px、1920px 均需检查。860px 以下侧栏折叠为模态导航，任务面板也转为模态抽屉。600px 以下采用窄屏控件尺寸，390px 默认两列；320px 等更窄视口允许一列，不能挤出横向滚动。

窄屏隐藏尺寸滑块和非必要的重复路径，保留作用域、选择、任务和返回。继续浏览保留图标入口与完整可访问名称。查看器可让侧边导航箭头移到图片区域的下沿，不能压缩图片到不可辨认的卡片中。

## 3. 视觉系统

使用 `tokens.css` 语义变量，不在页面新增一组私有近似颜色。

| 层级 | 字号与字重 |
| --- | --- |
| 应用名称 | 18px / 650 |
| 当前工作区标题 | 22px / 650，行高 1.35 |
| 整理区标题 / 对话框标题 | 18px / 600 |
| 面板标题 | 16px / 600 |
| 正文 / 卡片名称 | 14px / 400–600 |
| 次级标签、路径、元数据 | 12px / 400 |
| 状态栏和非关键细节 | 11px / 400，不用于错误原因与关键命令 |

使用 Windows 系统字体，无远程字体请求，无负字距，无随屏幕宽度变化的字号。命令按钮文字保持正常字距。

中性表面间使用分隔线与对齐，不把每个页面段落套成卡片。选中用青绿色边框、选中背景和复选框共同表达。绿色成功只用于真实结果，警告与删除危险分别使用琥珀和红色。

图标统一使用仓库 Lucide，默认 18px、线宽约 1.65；小型辅助图标 14/16px。工具图标提供悬停和键盘焦点工具提示，提示不得越出视口或被滚动容器截断。

浅色为初始外观，也支持深色与跟随系统。主题偏好只影响工作台，查看器固定中性深色。切换主题不重置选中项、位置或发起图片重扫描。

## 4. 位置与导航

- 侧栏显示当前图库的一级文件夹，数字为 `Group.image_count`，不是本页数量或图包数。状态、分类筛选可以组合，使用接口已有枚举。
- 面包屑至少保留图库、文件夹、当前图包。窄屏省略中间项，当前名称最后让位；详情可读完整相对路径。
- 图包名称相同时，显示父相对路径以消歧；路径太长可以截断，但信息面板完整换行，允许选择复制文本。
- “继续浏览”显示图包名与 `第 n / 总数`，进入原图片 ID；404 时说明图片已移除，回到仍有效的图包/文件夹，不偷偷跳到第一张冒充恢复成功。
- 从查看器返回保留原网格滚动锚点、显示刚看图片的边框；方向键切到后续图片再返回，也定位最后一张。
- 生产恢复以图片 ID 和虚拟列表锚点为准，不能只存像素滚动值。窗口缩放改变列数后仍保留相同首可见内容。
- 浏览器前进/后退和桌面重启恢复继续生效，不能为了模式切换清空路由记录。

## 5. 图片墙与选择

- 图包封面允许 `cover`；图片墙默认 `contain`，完整/填充是互斥模式。切换不改图片顺序、选择和几何尺寸。
- 静态封面不播放动图；动图使用精简的“动图”标识，不能将 GIF 显示成坏图。
- 图片下面常驻文件名。尺寸未补齐时显示“尺寸待补齐”，元数据错误不污染整面墙；文件大小未知用“—”。
- 封面失败占用原格子，显示错误类别和重试。错误原因取同一次请求结果，不为了探测再请求原图。
- 鼠标悬停、键盘聚焦可看到独立复选框。点击复选框进入批量选择，随后卡片点击只切换选择。窄屏通过“选择”显式进入。
- 进入选择后，上下文工具栏原位替换为数量、选中可见项、清空、删除与完成；不添加浮动操作岛，不使网格上下跳动。
- 多选上限 500。文案必须写“选中可见项”或“选中已载入项”，不声称选中了没有取回 ID 的全库数据。删除确认列出准确目标。
- Shift 范围选择仅针对已有连续索引和已加载条目；跨未加载页不默默发起全库枚举。键盘空格切换当前项，Enter 打开。
- 切换图包/文件夹清空该范围选择；打开任务面板、换主题和调整网格不清空。
- 现有“散图”保留明确名称，不能作为独立磁盘图包执行整包删除；进入图片墙逐张选择。

## 6. 查看器

- 深色画布充满可用区域，图片默认完整显示；横图、竖图、透明图、极宽图都不能拉伸变形。
- 透明图片使用中性棋盘底，棋盘只在图像区域出现，格子约 12px、低对比；不为普通 JPEG 铺棋盘。
- 顶部 56px 显示文件名、所属图包、当前位置、信息/更多/关闭。不得只显示一个计数而丢掉文件名。
- 使用适应窗口、缩小、放大、原始尺寸的熟悉图标。100% 沿用现有约定：一个原图像素占一个 CSS 像素；DPR 用于请求足够清晰的资源，不改变该比例。适应窗口默认只缩小不放大小图，不能以封面尺寸作为原始尺寸。
- 放大后可拖动，位移限制在可看见图片的范围；双击图片可在适应与原始尺寸间切换。双击不是打开图片的唯一方式。
- 左右键和按钮只在包内导航，到边界禁用并显示“已到当前图包末尾”，不循环、不跨包。抽样打开的图片也以其真实图包上下文导航。
- 胶片条只围绕当前位置生成有限窗口，当前项有边框与 `aria-current`。不为 8,000 张图包生成 8,000 个节点。
- GIF/WebP 动画只在查看器加载原始资源；可以保持原有预览到原图渐进替换，不能因换皮重新串行等待预览与原图。
- 大图未就绪时保留已显示的预览；快速切换取消或忽略过期结果，不让前一张图片覆盖当前位置。
- 工具可按原有规则隐去，但鼠标移动、聚焦和触摸可恢复；键盘焦点所在工具不能自动消失。
- 保留现有临时旋转、系统全屏、触摸平移/缩放和滑动导航。旋转只改变查看状态，不写回原文件；这些次要工具可收进更多菜单，不能在改版时直接丢掉。
- 失败原地显示“原图读取失败”和重试，仍能去上一张、下一张或退出。不用持续 Toast 掩盖主画面。

## 7. 整理区

抽样、相似图包、整包核验、清理检查作为整理页的四个工具。作用域固定显示当前文件夹，切换工具保留该作用域；在任务中打开结果定位到原文件夹与原任务 ID。

**抽样**：保留 20/40/100 数量选项，显示本批实际数量，换一批更新 seed。返回本批时保持 seed；不能每次渲染随机洗牌。卡片注明所属图包。

**相似图包**：左右并列封面和名称，分别显示匹配比例与指纹覆盖率。比例以各自分母计算，不能把 `left_match_rate` 和 `right_match_rate` 合成一个“重复率”。提示未建指纹会影响覆盖；只提供查看和整包核验入口。

**整包核验**：两侧选择器必须指向同一文件夹内不同图包。先显示尚未核验，受理后显示任务与进度，完成后显示以下结论之一：

| 结果 | 主结论 | 快捷删除依据 |
| --- | --- | --- |
| `exact_equal` | 两侧完全一致 | 用户选择保留一侧，删除确认仍需展示范围 |
| `left_contained` / `right_contained` | 指定一侧被另一侧完整包含 | 仅被包含的一侧可出现基于核验的回收入口 |
| 两侧均有独有文件 | 两侧各有独有内容 | 不提供核验推导的快捷删除；普通手动选择仍允许由用户决定 |
| 文件读取失败、任务中断、空图包 | 未能得出完整结论 | 不推导安全删除 |
| `Library.revision > result.revision` | 核验结果已过期 | 移除基于旧结果的快捷入口，提供重新核验 |

图包文件数、左右独有文件数和非图片文件必须可见；独有文件分页，显示相对路径。结果说明“内容相同”，不写“逐字节逐一对照”这种超出 SHA-256 实现事实的算法表述。不能把任务 `completed` 等同于两侧一致。

**清理检查**：显示空壳、含广告、不完整等现有分类，保留命中文件清单及原因。空壳也可能含文本文件，“0 张图片”不能写成“空文件夹”。删除仍走统一流程。

文件夹“保留/待整理/未标记”仅是 `/groups/{id}/review` 管理的状态，不变成每张图片的评分或收藏。

## 8. 任务与删除

任务面板默认不遮住整个桌面。显示任务种类、目标名称、当前状态、进度、最终数量和错误摘要。提供当前图库/类型/状态筛选与历史分页，正常自动维护默认折叠。

| 状态 | 界面规则 |
| --- | --- |
| `queued` | 排队中，不伪造百分比；可取消，符合既有规则时可暂停 |
| `running` | total 已知才显示比例；未知时显示阶段与已处理数量 |
| 前端控制请求待回应 | 按钮忙碌/禁用重复提交；“暂停中”是本地待确认，不新增后端枚举 |
| `paused` | 已暂停，保留进度，提供继续/取消 |
| `cancelling` | 正在取消，不先隐藏任务或标记完成 |
| `cancelled` | 已取消，显示最后已处理数量；已做的工作不会自动回滚 |
| `completed` | 显示业务结果；删除还需读逐项结果和失败数 |
| `failed` | 显示具体原因；任务可重新发起，不能复用“继续”伪装复活 |
| `interrupted` | 已中断，说明可重新开始；保留原记录 |

删除任务不提供暂停，其他按钮沿用 `lib/tasks.ts` 的能力判断。关闭面板不取消任务。缓存维护放在任务区，不在浏览默认工具栏常驻。

删除流程：准确目标 → 默认回收站确认 → 任务 ID/处理中 → 每项结果。确认按钮在受理前禁止重复点击，但不能在受理后直接显示“已删除”。

- 永久删除放在确认框中的显式复选项，选中后出现第二个确认复选框，再提交 `confirm_permanent: true`；不因上次使用而记住危险选项。
- 整包/整文件夹删除说明包含所有文件，显示图库、相对路径与范围；不允许同名目标仅显示名字而没有归属。
- 每项完成才从索引视图中移除；失败项保留，显示原因，允许只重试失败项。回收失败始终保持失败，不提供自动永久删除回退。
- 不做自定义“撤销删除”：应用没有恢复回收站条目的协议。可以说“已移到回收站”，不能显示无法兑现的撤销按钮。
- 查看核验过期不妨碍用户普通手动选择删除，但必须不再暗示该删除有新鲜核验保证。

## 9. 状态、文案与可访问性

| 场景 | 表达与恢复 |
| --- | --- |
| 首次索引 | 后端先就绪；显示枚举阶段和已发现数量，允许浏览已有结果 |
| 图库根目录离线 | 顶部一条状态带，保留上次索引与已有缓存；不可读取原图时给出原因 |
| SSE 断开 | 表示连接状态；重连后读快照并修复活动列表，不能只靠重播事件 |
| 全部为空 | 区分没有图库、没有图片、扫描中、筛选无结果；各自提供适当操作 |
| 分页失败 | 原位置重试该页，已有内容和选择保留，不重置全列表 |
| 缩略图失败 | 单项占位、原因和重试；不无限自动重试 |
| 长文件名 / 路径 | 单项截断＋完整可访问名称；详情换行，不能撑宽页面 |
| 任务失败 / 删除部分失败 | 结果面板常驻可再打开，错误不能只出现几秒钟 |

正文对比至少 4.5:1，图标/关键控件/焦点至少 3:1。状态用图标和文字，不只用色点。桌面点击目标默认 32px，窄屏 44px；密集的独立小控件至少符合 WCAG 2.2 的 24px 与间距要求。

对话框和窄屏抽屉限制背景焦点，Escape 关闭最上层非破坏性视图，关闭后焦点回到发起控件或仍存在的最近资源。桌面非模态面板不能意外锁住背景操作。

列表更新不逐张向屏幕阅读器播报；任务受理、失败、阶段完成用节制的 `aria-live`。图标按钮有可访问名称，模式控件有当前状态，加载占位不可被误认为真实资源。

动效为 120–180ms，遵守减弱动效；网格无错峰进场、悬停放大和持续闪烁。Toast 只提供短反馈，失败与操作报告有持久落点。

## 10. 数据与性能边界

分页默认 100、上限 500，保持现有总数和 revision 语义。屏幕改版不加全库请求、不挂载全库 DOM、不为每张图包补发封面请求。

保留现有预览并发 4、队列 128 和后端卷/解码预算，不因多开一套预载器而翻倍。图片墙档位由实际显示尺寸和 DPR 决定，不能统一请求 4200；查看器请求沿用既有渐进加载。

主题、侧栏和信息面板切换不应重新创建整批图片请求。资源离开预载窗口时取消/忽略结果并释放 Blob；关闭查看器不破坏后方图片墙的虚拟滚动状态。

本轮不新增 API。任意目录内容过滤、全局搜索、大小/日期排序、图片级标记若以后需要，先定义服务端语义再设计入口，不能用当前页数据假装完成。
