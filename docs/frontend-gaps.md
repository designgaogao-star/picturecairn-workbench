# 前端接口缺口（交后端负责人）

正式前端（`ui/`）联调时发现的接口缺口。每条写明场景、需要的字段或行为，以及前端目前的处理方式。

- P1：影响正确性或用户数据。
- P2：影响体验或性能。
- P3：规范与一致性。

## P1

### 1. 扫描状态残留

- **场景**：扫描进程崩溃、被结束或以非 `Cancelled` 的异常退出后，图库的 `scan_status` 一直停在 `scanning`/`pending`。`service.start()` 只中断活动任务，不复位图库状态。真实目录副本重启后仍是 `scanning`。
- **需要**：二选一：
  - 启动时处理没有存活扫描任务的图库：扫描到一半的复位为 `interrupted`；停在 `pending` 的重新排队扫描，或改为明确的“未扫描”状态。
  - 在 Library 上提供 `scan_task_id`，由前端判断。
- **前端现状**：
  - 没有存活扫描任务时，`scanning` 显示为“扫描中断”，`pending` 显示为“尚未扫描”，并提供“重新扫描”。
  - 为避免误判，任务列表加载后会再确认一次。

### 2. 维护线程无视 `--no-scan`

- **场景**：`_maintain` 固定每 600 秒运行一次（`gallery/service.py:122`），先 collect 再逐库扫描。用 `--no-scan --no-watch` 启动时也会运行，只读排查或演示时会意外扫描真实目录。
- **需要**：
  - `--no-scan` 同时关闭维护扫描，或增加单独的 `--no-maintenance`。
  - 间隔可配置。
  - 维护触发的任务标明来源（如 `trigger: "maintenance"`）。

### 3. 删除目标提前消失会让整个任务失败

- **场景**：选中的图片或图包在执行前已被外部移走，整个删除任务失败，且没有任何逐项记录。
- **需要**：逐项结果增加 `missing`（或 `skipped`）状态并继续处理其余目标，任务以部分成功结束。
- **前端现状**：只能显示任务级错误，无法列出哪些已处理。

### 4. 取消删除会丢弃已完成部分的结果

- **场景**：删除任务中途取消后，已移入回收站的项目没有结果记录。
- **需要**：取消时保留已处理项的逐项结果。

### 5. 散图可作为删除目标被接受

- **场景**：`POST /operations/delete` 接受散图（loose）伪图包作为 `package` 目标，语义未定义（是否删除文件夹根部的全部散图？）。
- **需要**：明确拒绝（409），或定义语义并写入契约。
- **前端现状**：不提供该入口。

### 6. 添加图库在 Busy 时半成功

- **场景**：`POST /libraries` 返回 503（Busy）时，图库已创建但未扫描。前端提示失败，刷新后却出现一个“尚未扫描”的图库。
- **需要**：Busy 时二选一：
  - 不创建，真正失败；
  - 返回 201 和 `scan_status: "pending"`，扫描稍后排队。

## P2

### 7. 删除后出现 2–3 个重叠扫描

- **场景**：删除完成后，删除流程、目录监视和维护各自触发扫描。
- **需要**：同一图库的扫描合并去重，排队中的扫描不重复入队。

### 8. 删除后的扫描报告“目录 0 · 文件 0 · 1 个目录读取失败”

- **场景**：增量扫描的目标目录已随删除消失，被记为读取失败。
- **需要**：目录不存在视为移除，不计入失败；统计填写实际数字。

### 9. 任务目标只有 ID

- **场景**：任务抽屉里，未被前端缓存的目标只能显示 ID。
- **需要**：`targets[]` 附带 `label`（名称）和 `rel`（相对路径）。

### 10. 任务完成后清空 `total`/`current`

- **场景**：已完成的任务无法显示“共处理 N 项”。
- **需要**：完成后保留最终计数。

### 11. `/tasks` 只返回最近 50 条且无筛选

- **场景**：维护扫描很快会把删除任务挤出这 50 条，用户找不到删除报告。
- **需要**：
  - 按 `type`、`status`、`library_id` 筛选并分页；
  - 或者让删除任务不受窗口限制。

### 12. 没有单个分组和单个图包的 GET

- **场景**：
  - 深链、刷新恢复、任务抽屉跳转都需要分组或图包详情，前端只能分页查找（最坏翻 20000 个分组）。
  - 任务抽屉因此只能链接已缓存的分组。
  - 浏览位置只能 `PUT /groups/{id}/position`；读取依赖分组列表里的 `resume_image_id`，无法单独刷新。
- **需要**：`GET /groups/{id}` 和 `GET /packages/{id}`，含以下字段：
  - `library_id`、`group_id`；
  - 名称、相对路径、计数；
  - `resume_image_id`。

### 13. 分组没有封面字段

- **场景**：首页每张文件夹卡片都要额外请求 `packages?offset=0&limit=1` 才能拿到封面，125 个文件夹就是 125 个请求。
- **需要**：Group 增加 `cover_id`（首个图包的封面）。
- **前端现状**：
  - 只为已挂载的卡片请求，并发 2；
  - 按从上到下的顺序请求；
  - 卡片滚出可见区后取消请求。

### 14. 相似图片对缺少图包 ID

- **场景**：图片对（Pair）只有图片 ID，无法直接打开所属图包或发起整包核验。
- **需要**：`left_package_id` 和 `right_package_id`。

### 15. 整包核验结果信息不足

- **场景**：
  - 任务载荷缺 `group_id`，任务抽屉无法跳回对应文件夹。
  - `ComparedFile` 没有路径，嵌套目录中的同名文件无法区分。
- **需要**：载荷带 `group_id`，`ComparedFile` 带 `rel`。

### 16. `package_pairs` 在 500 条处截断且没有总数

- **需要**：返回 `total` 或 `truncated`，并支持分页。

### 17. 清理检查的证据只有 ID

- **场景**：广告图等证据需要显示名称和所属图包。
- **需要**：证据项附带 `name` 和 `package_id`。

### 18. 清理检查忽略 `threshold` 参数

- **需要**：让参数生效，或从契约中移除。

### 19. revision 以图库为单位

- **场景**：任意变化都会让当前分组的数据失效，前端只能整页重读。
- **需要**：二选一：
  - `catalog` 事件带受影响的 `group_ids`/`package_ids`；
  - 改为分组级 revision。

### 20. 缩略图预热顺序随机

- **场景**：预热按随机 ID 顺序进行，首屏不会先完成。
- **需要**：按显示顺序预热（图包顺序，再按图片排序）。

### 21. 缩略图 `max-age=0`

- **场景**：每次进入图片墙，每张缩略图都会发一次条件请求（304），机械硬盘上尤其明显。
- **需要**：URL 带内容版本，响应使用 `immutable` 长缓存。

### 22. 图片请求失败时前端拿不到原因

- **场景**：`<img>` 加载失败时读不到 HTTP 状态，无法区分 503 忙（应重试）、404（已删除）、422（无法解码）。
- **需要**：二选一：
  - 图片元数据给出解码错误；
  - 提供轻量的状态查询。
- **前端现状**：`<img>` 失败后再用 `fetch` 请求一次，读出状态码。
  - 502–504：退避重试 3 次，之后显示“重试”。
  - 其他状态：显示后端返回的原因。
  - 文件取得到但浏览器解不开：提示文件可能已损坏。
  - 代价是每次失败多发一个请求。

## P3

### 23. 错误文本是原始 `str(exc)`

- **场景**：用户看到带 repr 路径的 Windows 原始异常文本。
- **需要**：`{"error": {"code": "...", "message": "...", "path": "..."}}`。
- **前端现状**：原样展示并截断。

### 24. SSE 心跳是注释行

- **场景**：`: ping` 对 EventSource 不可见，前端无法判断连接是否已僵死。
- **需要**：`event: ping`，并带时间戳。

### 25. 任务控制的状态码不一致

- **场景**：只有“暂停删除任务”返回 409，其他非法状态转换的返回不一致。
- **需要**：所有非法转换统一返回 409 和原因。

### 26. 图包记录只置 `present=0`，从不删除

- **需要**：明确各列表是否排除这些记录，以及清理策略。

### 27. `/cache` 没有响应 schema

- **需要**：补充 schema，`npm run contract` 才能生成类型。

### 28. 后端托管的是 `prototype/`，不是 `ui/dist`

- **需要**：`scripts/build.ps1` 构建 `ui/dist`，并由后端托管正式前端产物。

## 联调备注（不是接口缺口）

- Vite 开发代理在后端未启动时返回 502，前端把它视为离线。
- 开发用的 `?readonly` 只拦截标记、位置和删除，不拦截任务提交。
